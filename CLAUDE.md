# CLAUDE.md — Tidy Asset Allocation in R

Guidance for Claude Code sessions working on this book.

## What this is

A Quarto book in 28 chapters across eight parts, built on `PortfolioAnalytics`
2.1.2 and the tidyverse. Website-first, convertible to PDF.

**It is a course text.** It belongs in the same category as
*Tidy Finance with R* (@scheuch2023) and *Machine Learning for Factor Investing*
(@coqueret2020): explain what is being done, state it in mathematics, attribute
it to the literature, implement it in R, then hand the reader takeaways and
exercises. Not a handbook, not a research monograph, and not a package tour.

Three readers, in this order of priority. Every editorial decision is settled by
the first one and checked against the other two.

1. **A master's student in a portfolio management course.** The primary reader.
   They meet the material in a syllabus, work the exercises, and go on to use a
   teaching simulation downstream. The chapter must be teachable in one session.
2. **A quantitatively trained practitioner.** They already know the theory and
   want the working implementation, including the part the package makes hard.
   They are served by the same text, not by a separate track.
3. **A doctoral student or researcher.** They are not the audience for the prose,
   but they should be able to enter the literature through this book. That is
   what the citation density is for: the references must be complete enough that
   the book works as a route into the field.

The companion R package `tidypm` is a sibling directory (`../tidypm`), not a
subdirectory. It holds everything `PortfolioAnalytics` cannot do.

## How work gets done here

Code is written by one agent and audited by a second. The orchestrating session
holds the context, makes the decisions, verifies the result and commits.

1. **`r-empirics` writes.** It has Bash, so it runs its own code and reports
   real output rather than plausible output. A chapter's code is not "written"
   until it has executed.
2. **`code-reviewer` audits.** Read-only. It reports findings; it does not fix.
   Look specifically for look-ahead bias, survivorship, wrong inference, and
   silently swallowed failures.
3. **`r-empirics` fixes** anything the audit rates CRITICAL.
4. **The orchestrator verifies independently.** Agent findings are reported, not
   assumed. Re-run the numbers before they enter the prose.

Within a chapter the order is **code, then claims, then prose** — never prose
first. If you cannot state the claim after writing the code, the code has not
taught you anything yet.

## Package standards (tidypm)

Non-negotiable, because the package is the artefact that spreads:

- **Full roxygen2 documentation on every exported function.** `@param` for every
  argument, `@return` describing the actual shape, and `@examples` that run.
  `NAMESPACE` and `man/` are generated by `devtools::document()`, never edited
  by hand.
- **testthat for every exported function.** Test the contract, not the
  implementation: the property that must hold, the edge case that breaks it, and
  the error a wrong input must raise. A test that only checks the happy path is
  not finished.
- **Assumptions are arguments, not constants.** A default duration, a default
  loss rate, a default screen — each is exposed so a reader can vary it and see
  what moves.
- **Errors explain the fix.** `cli::cli_abort()` with what went wrong and what to
  do, not a bare `stop()`.
- `R CMD check` clean before anything is called done.

## The chapter contract — non-negotiable

Replaced the earlier "four beats" on 2026-09-12. The beats were a magazine

this book out of the category it is aiming at. Every chapter now runs:

contribution and neither reference book has it, so it survives the restructure;
it just stops being the skeleton.

chapter. Delete it when the chapter is written.

## The two axes, and how chapters declare their place

Two different cuts run through the book and were being confused with each other.
Settled with the user 2026-09-12:

- **Granularity (top-down).** Allocate across asset classes, then select within a
  class. This is the book's spine and the reason the **parts** are ordered as they
  are: classes in Parts III–V, sleeves in Part VI. A sixteen-asset problem is
  legible in a lecture; a one-hundred-and-eighty-one-asset one is not.
- **Horizon (strategic versus tactical).** Set a long-run policy from
  unconditional assumptions, then deviate using conditioning information.

They correlate in practice but are orthogonal in principle: tactical work happens
at class level too, and a permanent tilt inside a sleeve is strategic. **The parts
are named for granularity. Strategic and tactical are vocabulary**, defined once
in chapter 3 and then used to label what each chapter is doing. Students meet the
same language downstream, so it must appear — but on the chapters, not on the
parts.

## Assert that things fit together

Sebastian's rule, 2026-09-13, after two bugs of the same shape in two days.

Wherever two objects have to line up and nothing in the language enforces it,
**state the invariant in code**. Not a comment, an assertion that fails the
render. The cost is one line and the alternative is a defect that produces
plausible output forever.

Both bugs were silent, and both were caught only because something else was
being added nearby:

- three figures paired a table sorted by return with a vector in column order,
  plotting one asset's volatility against another's return
- a group constraint bound its limits positionally while `split()` returns its
  groups alphabetically, applying the equity limit to the commodity

Neither raised anything. Both produced a chart and a number that looked right.

The pattern to use:

```r
stopifnot(identical(names(grp), names(gmin)))       # order matches
stopifnot(all(colnames(R) %in% names(w)))           # universe matches
w <- w[colnames(R)]                                 # then index by name
```

Three places this comes up constantly in this book: weight vectors against the
columns of a return matrix, group or constraint vectors against a `split()`, and
anything joined to `moments`, which is sorted. Index by name, and assert it.

## Figures are built from one data frame

Added 2026-09-13, after three figures in chapter 9 were found plotting one
asset's volatility against another asset's return. The moments table is sorted by
return; `apply(R, 2, mean)` comes back in column order; pairing them by position
silently mismatches every point. It was invisible for as long as the points were
unlabelled grey dots.

**Assemble every coordinate into a single tidy frame before plotting, and index
by name rather than by position.** One row per plotted thing, with the label and
a `kind` column, then draw each layer by filtering that frame. A plot built from
parallel vectors can be wrong in a way no error will ever report; a plot built
from one frame cannot pair the wrong x with the wrong y, because they are in the
same row.

The same applies to anything read out of an `xts` object: subset by column name,
never by index, and let `zoo::index()` carry the dates rather than rebuilding
them.

Chapters draw on one of two, and must say which:

  reproduces offline, for every reader.
- **The real free sleeves** (Kenneth French, FRED, Moody's) reached through
  `pm_init()` / `pm_data()`. Used where a claim has to be about real markets,
  and in chapter 2, which is about building them. They keep their real dates.

### The modeled market: what it is, and how the book speaks about it

Settled with Sebastian 2026-11-09. Three statements, and every chapter keeps to
them:

1. **It is modeled, and contains no real data.** Factor models for bonds,
   credit, equities and commodities were estimated by historical simulation on
   market data from 1992 to 2022; the factors were replayed, the idiosyncratic
   components drawn, and the asset paths reassembled. No series is the history
   of a real security. The book says exactly this, estimation period included,
   where the data are introduced: chapter 2, appendix A, `?sim-market`.
2. **It runs on a model calendar.** Model years 1 to 31, written as the
   calendar years 2101 to 2131 (`tidypm::model_year()`: model year = year −
   2100). Monthly dates are true month ends, and every week lies in the month
   it compounds into.
3. **It can be shocked.** Every series is the output of a factor model, so the
   market can be re-run with its factors shocked, which a history cannot. An
   appendix on scenario analysis is planned for this (see `PLAN.md`).

### The calendar rule — binding on every chapter, solution, caption and comment

- **Never write a calendar year, a dated event or a historical name for
  anything in the modeled market.** Not "2008", not "the global financial
  crisis", not "COVID", not "the dot-com bust", not "October 2008", not "from
  2002". The sample is "the sample", "31 model years", "372 months". A point in
  it is "model year 17", or `fmt_model(d)` for "August of model year 17".
- **Episodes come from `sim_episodes` and `in_episode()`.** Four are named, for
  what happens in them: `equity_bear` ("the equity bear market"),
  `credit_crisis` ("the credit crisis"), `liquidity_shock` ("the liquidity
  shock") and `rates_shock` ("the rates shock"). The text uses those labels,
  and no chapter types a window:

  ```r
  crisis <- in_episode(zoo::index(R), "credit_crisis")
  ep     <- sim_episodes            # episode, label, start, end, description
  ```
- **No date literal in chapter code for the modeled market.** A position is
  derived, never typed: `zoo::index(R)[121]`, `model_year(d) >= 11`,
  `in_episode(d, "rates_shock")`. The out-of-sample start of the register is
  observation 121, the first month of model year 11.
- **Time axes use `scale_x_model()`** (in `R/_common.R`), which labels model
  years; a date in prose or in a table uses `fmt_model()` or `model_year()`.
  Never `format(d, "%Y")` and never a raw date printed into the text.
- **Raw output may show model dates.** When a chunk prints a data object as it
  is (`head(R)`, `glimpse()`), its date column shows `2101-01-31` and the like.
  That is the model calendar itself and is fine. The rule governs what we write
  and draw: prose, captions, the tables we format, and axes.
- **The literature keeps its dates.** A cited study's sample, "the 1987 crash"
  in someone else's paper, and the real-data sleeves of `pm_data()` are
  untouched. The rule is about the modeled market only.
- The book says how the market was built; it does not hand out a calendar date
  for each of its months. Do not explain or discuss the rule in the book, and
  never map a model year to a calendar year anywhere in it.

### The render output lives off the synced tree

`output-dir` in `_quarto.yml` is `../../../../tmp/tidyaa_book`, i.e. `D:/tmp/tidyaa_book`.
Quarto always joins `output-dir` against the project directory, so it must be a
**relative** path, and since the project is on `D:` the target must be on `D:` too.
An absolute `C:/...` produced the impossible path
`D:/.../Tidy_Asset_Allocation/C:/R/tidyaa_book` and the render died at once.

and Quarto creates an empty `chapters/NN_files/` for every stub chapter with no

Do not remove them, and do not put the placeholder one level higher: Quarto
`readdir`s each entry directly under `NN_files/` and expects only directories there.

`*_files/` is gitignored, so the placeholders never reach the repo.

### Never interrupt a render

Quarto writes each page's HTML into the project directory and then *moves* it to
`output-dir`. Kill a render between those two steps and the half-finished
`.html` files stay behind on the synced tree. SharePoint then picks them up,
starts uploading, and writes conflict copies named `<page>-IT-00075.html` after
the machine. The next render fails on the move with

```
ERROR: Die heruntergeladenen Daten konnten vom Cloudsynchronisierungsanbieter
nicht überprüft werden. (os error 383): rename '...\index.html' -> 'D:\tmp\tidyaa_book\index.html'
```

which reads like a Quarto bug and is not one. Learned 2026-09-12 after stopping
two renders to pick up edits mid-flight; it left 50 stray files.

Let a render finish, or accept that the recovery is:

```powershell
Remove-Item .\*.html, .\chapters\*.html
```

No `.html` file in the project tree is a source, so that delete is always safe.

### The renv trap — read before running any R script

`renv` activates through the project's `.Rprofile`, which R sources **at
startup**, from the working directory R was launched in. A script that calls
`setwd()` internally is already too late: renv is not active, `.libPaths()[1]`
is the shared library, and `renv::install()` writes there.

This mistake was made once in this project and put two packages into the user's
shared library. Always launch with the working directory already set:

```powershell
Set-Location "...\Tidy_Asset_Allocation"
& "C:\R\R-4.6.1\bin\Rscript.exe" script.R
```

and guard the script itself:

```r
stopifnot(grepl("Tidy_Asset_Allocation", .libPaths()[1], fixed = TRUE))
```

If a run is killed mid-install, remove the stale lock before retrying:
`renv/library/windows/R-4.6/*/00LOCK-*`.

## Two kinds of work, two sessions

**The only interface is the pinned SHA in `renv.lock`.** Handover, in this order:

1. the branch is finished, the full `testthat` suite is no worse than `master`,
   and it is pushed;
2. in the book session, `renv::install("sstoeckl/PortfolioAnalytics@<sha>")` and
   `renv::snapshot()`;
3. re-render the chapters that depend on it and re-pin their numbers in
   `PLAN.md`.

Repin **between** chapters, never inside a half-written one. A force-push
invalidates a pinned SHA, so a rewritten branch means step 2 again.

`tidyaa_pa_patched()` in `R/_common.R` is the tripwire: if a chapter starts with
its warning, the installed build is not the pinned one. Repin before believing
any number.

## The review channel

Three ways in, settled 2026-09-13. All of them end in the same place.

**Word, for a chapter that is finished.** `python tools/make-review-docx.py
<slug>` builds one chapter as a Word document into `review/` from the cached
render (`_freeze/`), Sebastian comments in Word, the file comes back, and
`tools/extract-docx-comments.py` pulls out every comment together with the
passage it is anchored to. Never `quarto render <chapter> --to docx`: in this
project a single-file render renders all 39 files (HTML too — there is no
single-chapter render here; `tools/run-chapter.R` executes one chapter's code
instead), and `--output-dir review` deletes the directory first. The full
procedure is in `review/README.md`.

**`REVIEW.md`, for a longer remark** that is not tied to one sentence. Read it at
the start of a book session and work the open items before anything else.

**`<!-- SS: ... -->` in the `.qmd`, for a short local note.** Grep for them when a
chapter is opened and answer in place.

**Hypothesis and giscus, for every other reader** (set up 2026-11-11). The
site loads the Hypothesis client (`comments:` in `_quarto.yml`), so a reviewer
selects a passage and annotates it; reviewers post to a private group whose
invitation Sebastian sends. `python tools/fetch-hypothesis.py --markdown`
pulls the annotations with their anchors, in the shape of the Word extractor
(token in `review/.hypothesis.token`, group id in `review/.hypothesis.group`,
both gitignored). A giscus thread (GitHub Discussions, category General,
enabled 2026-11-11) sits under every page for remarks about a chapter as a
whole; the giscus app has to be installed on the repository once, by
Sebastian, at github.com/apps/giscus, or the box shows an error.
`REVIEWING.md` is the reviewer-facing guide: the three ways to comment, the
four review levels (draft, alpha, beta, final), the order of the alpha round,
and what happens to a comment. Each chapter's level is one line in
`review/status.csv`, shown in the banner under its title
(`tools/chapter-banner.lua`) and tabulated in the colophon; move a chapter by
editing that line, never the chapter.

### Every comment lands in `REVIEW-LOG.md`

Not as a courtesy. A comment that is fixed and forgotten arrives again, and the
log is what makes the second arrival visible as a second arrival. At that point
it stops being a fix and is promoted into this file as a rule, and the log
records that it was.

Three rules here came from review comments rather than from planning: figures
built from one data frame, asserting that things fit together, and
cross-references in both directions. None of them was foreseen.

## Cross-references, in both directions

Sebastian's requirement, 2026-09-13, and it is a content rule rather than a
formatting one. A chapter that refers to nothing and is referred to by nothing
reads as a chapter from a different book, and nothing in the render complains.

Every written narrative chapter refers **back to at least three** earlier
chapters, **forward to at least two** later ones, and is **referred to by at
least three** others. Appendices and the reference list are exempt from the
density rule but not from the dangling check.

```bash
python tools/check-crossrefs.py            # report
python tools/check-crossrefs.py --strict   # exit 1 on a violation
```

Run it before committing a chapter. It also reports dangling references, which
Quarto otherwise reports only at the end of an hour-long render.

A reference goes **inside the clause that needs it**, never bolted onto the end
of a paragraph. "Both are estimates, produced by the methods of @sec-... and
@sec-... and carrying the errors those chapters measure" is navigation. "See also
@sec-..." is decoration.

## Conventions

- Chapters run from the **project root** (`execute-dir: project` in
  `_quarto.yml`), so `source("R/_common.R")` and `data/...` work everywhere.
- `R/_common.R` is sourced by every chapter: seed 1602, options, the ggplot
  theme. Keep it small — chapter-specific setup belongs in the chapter.
- `R/_dependencies.R` exists only so `renv` can discover packages while the
  chapters are stubs. It is never sourced. Update it when a chapter's imports
  change, then `renv::snapshot()`.
- Colors and typefaces come from `_brand.yml`; `assets/css/custom.scss` layers
  on top. Do not hard-code colors in a chapter — use `tidyaa_colors`.
- Cross-reference sections as `@sec-<chapter-slug>-<section>`, e.g.
  `@sec-13-solvers-implementation`.

## Design

Rebuilt 2026-09-12 to follow Tidy Finance, whose design is deliberately almost
nothing: the stock `cosmo` Bootstrap theme, one accent color, and a short
stylesheet that removes ornament. Their entire theme file is three declarations.

- `theme: [cosmo, brand, assets/css/custom.scss]`. The order matters: cosmo
  carries the page, `_brand.yml` sets palette and typeface, `custom.scss` only
  removes ornament and styles the title block.
- **The accent is a light blue**, `#2E77A6`, with `#5FA8D3` for rules and
  markers and `#EAF2F8` as the wash. Tidy Finance uses a teal, so the two books
  read as siblings without being confused for each other.
- **One typeface**, Source Sans 3, for body and headings alike. The earlier
  serif/sans pairing signalled "essay".
- **The title block is the one deliberate departure**: a short light-blue accent
  bar above the title. That is the book's own mark.
- **No dark mode.** Every figure is a light-ground PNG, so a dark page inverts
  the text and leaves the plots behind. Tidy Finance ships light only.

### A Quarto trap worth keeping

`_brand.yml` emits `--bs-body-font-family: Source Sans 3` **unquoted**. A CSS
family name whose final token begins with a digit is invalid unquoted, so the
browser discards the declaration and falls back to its default serif — the book
rendered in Times and nothing warned. The same applies to Source Serif 4 or any
face with a numeric suffix. `custom.scss` therefore re-declares the three font
stacks quoted, with real fallbacks. Do not remove that block.

## Which package does what

Settled with the user. Recorded in full in `chapters/93-package-notes.qmd`.

- **`PerformanceAnalytics` is the engine** for moments, distributions, drawdowns,
  alphas and betas, active-management measures and exploratory charts. Stable
  since 2007 and already a hard dependency. Check it before writing anything by
  hand — `CAPM.beta.bull()`/`CAPM.beta.bear()`, `table.DownsideRisk()`,
  `table.Distributions()`, `table.CAPM()` and 33 `chart.*` functions cover most
  of chapters 4 and 24 already.
- **`tidyquant`** at the tibble boundary (`tq_performance()`).
- **`tidyfinance` for data access only, never estimation.** Pre-1.0, interfaces
  still moving. It is the only source for JKP, Goyal–Welch and the WRDS
  substitutes, and that is what it is for.
- **Hand-written code only where none of them has it.** Rolling betas as a table
  are such a case (`chart.RollingRegression()` plots but returns nothing), so
  compose `zoo::rollapply()` with `CAPM.beta()`.
- `uncertaintymeasures` installs from GitHub (`sstoeckl/uncertaintymeasures`) and
  the turbulence excursus renders live against it, not from a frozen figure.

## Parked until the data exists

Chapter 20 in full, and the value-factor material in chapters 16, 18 and 21.
Both need firm fundamentals and ESG *levels*, which this export does not carry:
it holds 1,113 ESG rating **changes** but no starting grade, so cumulating them
gives a level up to an unknown constant. Real vendor fundamentals cannot be
shipped, and attaching them to simulated prices would pair a real numerator with
an artificial denominator. The route agreed is to simulate both, calibrated to
the real cross-sectional distributions — ESG first, since the change path
already exists and only a starting level is missing. Everything else in the book
runs on returns and is unaffected.

## Known package traps to teach, not hide

These are documented in the book on purpose. Do not work around them silently.

| Trap | Where |
|---|---|
| `optimize.portfolio.rebalancing()` reports nothing when a solver fails in a period | ch. 25 — issue #45 |
| `maxSR` defaults `FALSE`, `maxSTARR`/`CSMratio`/`EQSratio` default `TRUE` | ch. 10, 13 |
| CSM unavailable in metaheuristics (empty block in `constrained_objective.R`) | ch. 10 — issue #51 |
| EQS ratio not normalised post-solve, so box/group constraints may not bind | ch. 10 |
| Turnover is a penalty under CVXR, a hard constraint under ROI | ch. 23 |
| Proportional transaction costs exist only under ROI | ch. 23 |
| Position limits require MILP (ROI or Rglpk) | ch. 12 |
| Diversification constraint exists only under metaheuristics | ch. 12 |
| Risk budgeting has no convex solver at all | ch. 14 |
| `random_portfolios()` ignores factor-exposure bounds | ch. 28 |
| `risk_aversion` is γ/2, not γ | ch. 3, appendix B |
| `ES()` defaults to the Cornish–Fisher estimate, not the historical one | ch. 4, 10 |
| `Return.portfolio()` back-fills equal weights before the first weight vector | ch. 23 |
| `max_pos` on ROI's quadratic path is dropped without a message, on the pinned fork as on CRAN; honored only on the MILP paths | ch. 12, appendix C |
| `leverage_exposure` under ROI returns the long-only answer: the ROI problem is built without bounds | ch. 12 |
| `factor_exposure_constraint()` binds its matrix by position, never by name; an exact target is reported infeasible by quadprog; an unmeetable bound returns NA weights silently | ch. 22 |
| `EQS` squares the positive part of the return, not the loss; ROI ignores `method = "modified"` for ES | ch. 10 |
| A custom objective defined outside the global environment is silently skipped by the metaheuristics | ch. 11 |
| `black.litterman()` recycles a short `Views` vector and uses the full `PΣP'` as Ω; `ac.ranking()` ignores `max.value` | ch. 17 |
| `regime.portfolios()` looks the regime up contemporaneously at the rebalancing date; 0/1 coding gives stress months the calm specification | ch. 19 |
| `random_portfolios()` breaches a factor-exposure cap in every draw and `optimize_method = "random"` returns the breach silently | ch. 28 |
| `turnover()` divides by the number of assets, not by two | ch. 23 |

## Tools, and the one render rule

There is **no single-chapter render** in this project: `quarto render
chapters/NN.qmd` renders all 39 files in every format of `_quarto.yml`,
including PDF figures, and takes the better part of an hour. So:

```bash
# execute one chapter's code without rendering (purls the chunks, runs them in
# order from the project root, reports the first error by chunk label);
# inline `r ...` expressions are not evaluated -- check those by eye
& "C:\R\R-4.6.1\bin\Rscript.exe" tools/run-chapter.R chapters/09-mean-variance.qmd

# knit one chapter to markdown with every inline expression evaluated, outside
# the project; prints the path. This is how a sentence is checked against its number
& "C:\R\R-4.6.1\bin\Rscript.exe" tools/knit-chapter.R chapters/09-mean-variance.qmd

python tools/check-crossrefs.py            # dangling and density, before a commit
python tools/check-bib.py --new            # every DOI not yet checked against Crossref
python tools/make-review-docx.py 09-mean-variance   # Word for Sebastian, from _freeze
python tools/extract-docx-comments.py review/09-mean-variance.docx
python tools/fetch-hypothesis.py --markdown          # annotations from the site, same shape
python tools/build-code.py                 # the code downloads, before every render

# one slide deck, standalone, lands beside its source as slides/<slug>.html
& "C:\R\RStudio\resources\app\bin\quarto\bin\quarto.exe" render slides/09-mean-variance.qmd

& "C:\R\R-4.6.1\bin\Rscript.exe" R/verify-claims.R   # after any data change
& "C:\R\R-4.6.1\bin\Rscript.exe" R/oos-sweep.R       # the register, ~10 min; delete output/tables/oos/*.csv first to force
```

A chapter is not written until `run-chapter.R` exits 0 on it and on its
solutions file in `chapters/solutions/`. Render the whole book, HTML only,
when a wave of chapters is done, and never interrupt it:

```bash
& "C:\R\RStudio\resources\app\bin\quarto\bin\quarto.exe" render --to html
python tools/fix-theme-links.py           # always, see "After every render"
```

**Slides** live in `slides/<slug>.qmd` (revealjs, `embed-resources: true`,
the shared `slides/tidyaa-slides.scss`). A file outside the chapter list
renders standalone, from the project root with renv active, and lands next
to its source as `slides/<slug>.html` (gitignored); the banner links a deck
as soon as `slides/<slug>.qmd` exists. A deck reuses the chapter's code
through `knitr::opts_knit$set(root.dir = "code")` and
`knitr::read_chunk("<slug>.R")`, so a figure on a slide is the chapter's
figure and nothing is maintained twice. Chapter 9 is the pilot
(2026-11-11); the rest follow once its format is approved.

To publish, `bash tools/publish-gh-pages.sh` (fixes the theme links, copies
`slides/*.html` into the site, mirrors the output into a clone of the
`gh-pages` branch at `D:/tmp/tidyaa_ghpages`, commits, pushes). The site is served at
https://sstoeckl.github.io/tidy-asset-allocation/ and reaches readers as
https://www.tidy-pm.com/dev/ through a proxy rule (`_book/_redirects`) in the
old book's `publish` branch on Netlify, where the old book stays at the root
until this one replaces it. Both repositories are public with a fresh history
(2026-11-11); never push the local `history-local` branches, which carry the
source calendar.

To look at the result, `.claude/launch.json` (at the parent folder the app
treats as the project root) defines a static server `book` on port 4200 serving
`D:/tmp/tidyaa_book`; `quarto preview` would re-render.
