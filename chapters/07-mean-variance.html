9  The Mean-Variance Baseline

The question. What does the textbook answer look like on these asset classes?

Mean-variance optimisation is the first thing anybody learns and the last thing anybody trusts. This chapter does it properly, on the sixteen risky class series of Section 3.1, and then shows why the picture that comes out is worth less than it looks.

Every moment here is estimated on the full sample. Nobody standing in 1992 knew the 2022 covariance matrix, so what follows is descriptive rather than implementable; Section 24.1 does the honest version. The point of this chapter is what the textbook answer looks like when the inputs are not invented.

R  <- as_xts_pm(sim_class_returns_monthly, date, class, return)
R  <- R[, !grepl("money_market", colnames(R))]
rf <- sim_riskfree_monthly$return

# A tangency portfolio only exists relative to a risk-free rate, and
# PortfolioAnalytics has no argument for one. The returns handed to the
# optimiser are therefore already in excess of the bill -- which is also the
# only formulation that stays coherent once weights are allowed to sum to less
# than one. See @sec-03-returns-and-the-investor-hands-on.
Re <- R - rf

dim(Re)
#> [1] 372  16
range(zoo::index(Re))
#> [1] "1992-01-31" "2022-12-31"

9.1 What you need

Before any optimiser runs, look at what you are feeding it. Mean-variance consumes exactly two numbers per asset and one per pair, and on this panel those numbers are lopsided.

ann_ret <- function(x) prod(1 + x)^(12 / length(x)) - 1
ann_vol <- function(x) stats::sd(x) * sqrt(12)

moments <- tibble::tibble(
  asset = colnames(R),
  mean_arith = apply(R, 2, mean) * 12,
  mean_comp  = apply(R, 2, ann_ret),
  vol        = apply(R, 2, ann_vol)
) |>
  dplyr::mutate(drag = mean_arith - mean_comp) |>
  dplyr::arrange(dplyr::desc(mean_comp))

vol_spread <- max(moments$vol) / min(moments$vol)
mean_cor   <- mean(stats::cor(R)[upper.tri(stats::cor(R))])
c(vol_spread = vol_spread, mean_correlation = mean_cor)
#>       vol_spread mean_correlation 
#>           5.3227           0.3538

The most volatile series is 5.3 times the least, and the average pairwise correlation is 0.35. Both numbers decide what the frontier can do, and Section 9.4 returns to them.

Note the two columns for the mean. The arithmetic average is what the optimiser uses, because variance is defined around it; the compounded figure is what an investor earns. The gap is the variance drag, and it is not decoration:

9.1.1 Half the universe is beaten before the optimiser starts

# j dominates i if it has a weakly higher mean and a weakly lower volatility.
# A sample statement with no test attached: it says what happened, not what
# will happen.
dominated <- vapply(seq_len(nrow(moments)), function(i) {
  any(moments$mean_comp >= moments$mean_comp[i] &
      moments$vol       <= moments$vol[i] &
      seq_len(nrow(moments)) != i)
}, logical(1))

moments$asset[dominated]
#>  [1] "CH_equity"        "EU_equity"        "UK_credit"        "CH_credit"       
#>  [5] "GLOBAL_commodity" "CH_government"    "UK_government"    "JP_credit"       
#>  [9] "EU_credit"        "JP_equity"        "JP_government"    "EU_government"

12 of 16 series are beaten on both axes by at least one other. JP_equity is beaten by eleven of the fifteen alternatives. None of that needs an optimiser: it is visible in a scatter plot, and a reader who cannot see it in the plot will not see it in a weight vector either.

9.1.2 The specification is four lines

base_spec <- portfolio.spec(assets = colnames(Re)) |>
  add.constraint(type = "full_investment") |>   # weights sum to one
  add.constraint(type = "long_only")            # 0 <= w <= 1

min_var_spec <- base_spec |>
  add.objective(type = "risk", name = "var")

w_gmv <- extractWeights(optimize.portfolio(Re, min_var_spec, optimize_method = "ROI"))
round(w_gmv[w_gmv > 0.005], 4)
#> GLOBAL_commodity        JP_equity        US_equity    US_government 
#>           0.0591           0.0259           0.0769           0.8375
S <- stats::cov(Re)
mu <- colMeans(Re)
p_vol <- function(w) sqrt(as.numeric(t(w) %*% S %*% w)) * sqrt(12)
p_ret <- function(w) sum(mu * w) * 12
p_sr  <- function(w) p_ret(w) / p_vol(w)

c(volatility = p_vol(w_gmv), excess_return = p_ret(w_gmv), sharpe = p_sr(w_gmv))
#>    volatility excess_return        sharpe 
#>       0.04139       0.02235       0.54008

The minimum-variance portfolio holds 4 of the sixteen series and puts 84% of the money in US_government. That is not a subtle allocation. It is what happens when one series has a volatility of 4.7% and the next lowest is 7.2%: minimising variance means buying the quiet asset and adding whatever else reduces the total.

9.1.3 The tangency portfolio, and where it comes from

The maximum-Sharpe portfolio is the point where a line from the risk-free rate touches the frontier. PortfolioAnalytics offers maxSR = TRUE for it, and Section 9.2 explains why this book does not use it. The portable route is to compute the frontier and read the best point off it.

ef_spec <- base_spec |>
  add.objective(type = "return", name = "mean") |>
  add.objective(type = "risk",   name = "StdDev")

ef <- create.EfficientFrontier(Re, ef_spec, type = "mean-StdDev", n.portfolios = 200)

# `ef$frontier` is a matrix carrying a class attribute, and `as.data.frame()`
# dispatches on that class: it returns a single column of 3,762 numbers rather
# than 198 rows of 19. Strip the class first, or index it as the matrix it is.
fr <- as.data.frame(unclass(ef$frontier))

# Returns are already in excess of the bill, so the Sharpe ratio is the ratio
# itself: no risk-free rate to subtract.
fr$sharpe <- fr$mean / fr$StdDev
i_tan <- which.max(fr$sharpe)

wcols <- grep("^w[.]", colnames(fr))
w_tan <- setNames(as.numeric(fr[i_tan, wcols]), sub("^w[.]", "", colnames(fr)[wcols]))
w_tan <- w_tan[colnames(Re)]
round(w_tan[w_tan > 0.005], 4)
#>        CH_equity GLOBAL_commodity        UK_equity        US_credit 
#>           0.0855           0.0339           0.1101           0.1374 
#>        US_equity    US_government 
#>           0.0416           0.5915

Two things in that table are worth carrying forward.

The tangency portfolio beats a naive 60/40 by 0.28 of Sharpe ratio — a large margin, and entirely in-sample. And it holds 13.7% in US_credit, the series with a skewness of -1.49 and the single worst month anywhere in this market. The optimiser buys the asymmetry, because variance cannot see it. That is the opening of Section 10.1, and it is not a contrived example: it fell out of the standard procedure applied to the standard inputs.

9.2 How to actually do it

Three ways this goes wrong quietly. All three produce an object that looks like a solved portfolio.

9.2.1 The solver you were told to use is the wrong one

Most published examples reach for DEoptim. That advice predates the convex solvers in the package and is now not merely slow but wrong: minimum variance under a budget and a sign constraint is a quadratic program, and a differential-evolution search does not solve quadratic programs, it approximates them. Section 13.1 measures the size of the approximation — on a problem with a known answer the metaheuristics reach 53 to 72 per cent of the attainable optimum, while ROI reaches 100 per cent in four seconds.

Use ROI for a quadratic program. Reach for a metaheuristic only when the problem is genuinely not convex, and then check the answer.

9.2.2 A solver name that is not on a list nobody publishes

The modern incantation is optimize_method = c("CVXR", "OSQP"). The obvious reading of that vector is wrong. Inside optimize.portfolio():

if (length(optimize_method) == 2)
  optimize_method <- optimize_method[2]
else optimize_method <- optimize_method[1]

The first element is discarded. Dispatch happens on the second, matched against a hard-coded list of names.

pa_cvxr_solvers <- c("CBC", "GLPK", "GLPK_MI", "OSQP", "CPLEX",
                     "SCS", "ECOS", "GUROBI", "MOSEK")
setdiff(CVXR::installed_solvers(), pa_cvxr_solvers)
#> [1] "CLARABEL" "HIGHS"

CLARABEL is installed, is CVXR’s own default interior-point solver, and is not on the list. Asking for it raises nothing.

opt_bad <- optimize.portfolio(Re, min_var_spec,
                              optimize_method = c("CVXR", "CLARABEL"))
c(class = class(opt_bad)[1],
  has_weights = !is.null(extractWeights(opt_bad)),
  elapsed = unname(opt_bad$elapsed_time))
#>                         class                   has_weights 
#> "optimize.portfolio.CLARABEL"                       "FALSE" 
#>                       elapsed 
#>         "0.00706005096435547"

The call falls through every branch and returns a shell with a plausible class and no weights. In a rebalancing loop that becomes a period of NULL, which is Section 24.2’s whole subject. The guard is three lines and belongs in anything that solves more than once.

solve_checked <- function(R, spec, ...) {
  out <- optimize.portfolio(R, spec, ...)
  w <- extractWeights(out)
  if (is.null(w) || anyNA(w)) {
    cli::cli_abort(c(
      "The solver returned no usable weights.",
      "i" = "optimize.portfolio() returned an object of class {.cls {class(out)[1]}}.",
      ">" = "If you are using CVXR, the second element of {.arg optimize_method}
             must be one of {.val {pa_cvxr_solvers}}."
    ))
  }
  out
}

try(solve_checked(Re, min_var_spec, optimize_method = c("CVXR", "CLARABEL")))
#> Error in solve_checked(Re, min_var_spec, optimize_method = c("CVXR", "CLARABEL")) : 
#>   The solver returned no usable weights.
#> ℹ optimize.portfolio() returned an object of class
#>   <optimize.portfolio.CLARABEL>.
#> → If you are using CVXR, the second element of `optimize_method` must be one of
#>   "CBC", "GLPK", "GLPK_MI", "OSQP", "CPLEX", "SCS", "ECOS", "GUROBI", and
#>   "MOSEK".

This guard catches a second failure that has nothing to do with solver names. On the CRAN release of PortfolioAnalytics, an exact full_investment constraint is encoded as two opposing inequality rows, which are simultaneously active and linearly dependent; quadprog then reports the problem infeasible and ROI returns NA weights without raising. Measured on this data, that fails in 37 of 312 rolling sixty-month minimum-variance windows — for a constraint set consisting of nothing but sum(w) = 1 and 0 <= w <= 1. The fix is recorded in Appendix B. Until it reaches CRAN, solve_checked() is what stands between you and a backtest with holes in it.

9.2.3 A return target is not always a return target

The target return can go on a constraint or on the return objective, and the backends disagree about what the second means.

target_monthly <- as.numeric(quantile(mu, 0.75))

on_constraint <- base_spec |>
  add.constraint(type = "return", return_target = target_monthly) |>
  add.objective(type = "risk", name = "var")

on_objective <- base_spec |>
  add.objective(type = "return", name = "mean", target = target_monthly) |>
  add.objective(type = "risk", name = "var")

achieved <- function(spec, method) {
  w <- extractWeights(optimize.portfolio(Re, spec, optimize_method = method))
  sum(w * mu)
}

tibble::tibble(
  route = c("constraint, ROI", "constraint, CVXR/OSQP",
            "objective, ROI",  "objective, CVXR/OSQP"),
  achieved = c(achieved(on_constraint, "ROI"),
               achieved(on_constraint, c("CVXR", "OSQP")),
               achieved(on_objective,  "ROI"),
               achieved(on_objective,  c("CVXR", "OSQP")))
) |>
  dplyr::mutate(target = target_monthly,
                hit = abs(achieved - target) < 1e-8)
#> # A tibble: 4 × 4
#>   route                 achieved  target hit  
#>   <chr>                    <dbl>   <dbl> <lgl>
#> 1 constraint, ROI        0.00379 0.00379 TRUE 
#> 2 constraint, CVXR/OSQP  0.00379 0.00379 TRUE 
#> 3 objective, ROI         0.00379 0.00379 TRUE 
#> 4 objective, CVXR/OSQP   0.00882 0.00379 FALSE

Under ROI the objective’s target is honoured. Under CVXR it is read only when optimize.portfolio() is called internally with ef = TRUE, which happens from meanvar.efficient.frontier() and nowhere else. On a direct call the target is dropped and the solver maximises return instead, silently. Put the target on the constraint. It is the portable form and it is the one that means what it says.

9.3 What else is in there

chart.EfficientFrontier() will draw the frontier, the assets, the capital market line and the tangency point in a single call — and it computes the tangency correctly, by taking the highest Sharpe ratio among the frontier points rather than by calling maxSR.

chart.EfficientFrontier(ef, match.col = "StdDev", tangent.line = TRUE, rf = 0,
                        main = "", RAR.text = "Sharpe")

Two defaults will catch you. rf = 0 is the default, so without an argument the tangent is drawn to a zero rate and nobody is told — harmless here, because the returns are already excess, and wrong everywhere else. And match.col = "ES" is the default, so a mean-StdDev frontier drawn without match.col = "StdDev" looks for a column that does not exist.

9.4 Why it works

9.4.1 The frontier is a set of answers, not an object

There is no single problem whose solution is the efficient frontier. There are as many problems as points, each a separate quadratic program with its own target return, and the frontier is the set of their answers plotted together.

9.4.2 The left end is stable and the right end is not

The left end of the frontier is decided by the covariance matrix. Everything to the right of it is decided by the mean vector, and means are estimated far worse than variances from the same sample — Section 3.2 measured the rolling mean wandering by more than its own level while volatility moved by a third of its own.

A block bootstrap makes the consequence concrete. Draw the same thirty-one years in twelve-month blocks, re-optimise, and ask how far the answer moves.

set.seed(1602)

block_index <- function(n, block = 12L) {
  starts <- sample.int(n - block + 1L, ceiling(n / block), replace = TRUE)
  as.vector(outer(0:(block - 1L), starts, "+"))[seq_len(n)]
}

# Half the L1 distance between two long-only weight vectors: the share of the
# portfolio that must change hands to get from one to the other. The guard is
# not decoration -- given NULL, the unguarded arithmetic returns zero, and a
# failed solve would enter the sample as a portfolio that did not move.
turnover <- function(w1, w2) {
  if (is.null(w1) || is.null(w2)) stop("a failed solve is not a turnover of zero")
  sum(abs(w1[names(w2)] - w2)) / 2
}

B <- 200L
boot <- vapply(seq_len(B), function(b) {
  Rb <- xts::xts(zoo::coredata(Re)[block_index(nrow(Re)), ], order.by = zoo::index(Re))
  wg <- extractWeights(solve_checked(Rb, min_var_spec, optimize_method = "ROI"))
  fb <- as.data.frame(unclass(
    create.EfficientFrontier(Rb, ef_spec, type = "mean-StdDev",
                             n.portfolios = 60)$frontier))
  wt <- setNames(as.numeric(fb[which.max(fb$mean / fb$StdDev), wcols]),
                 sub("^w[.]", "", colnames(fb)[wcols]))
  c(gmv = turnover(wg[colnames(Re)], w_gmv),
    tangency = turnover(wt[colnames(Re)], w_tan))
}, numeric(2))

The tangency portfolio moves 5.4 times as far as the minimum-variance portfolio, on identical data drawn a different way. In the worst twentieth of draws it asks you to trade 66% of the portfolio; the minimum-variance answer never asks for more than 10%.

Nothing changed except the sample. The right end of the frontier is not more aggressive than the left, it is less known — and that is a different kind of problem, because you cannot fix it by holding less of it.

9.4.3 What the frontier actually trades on

It is tempting to attribute the minimum-variance portfolio’s low volatility to diversification. Mostly it is not.

The cleanest way to see this is to run the same chapter twice, once on a universe built to be heterogeneous and once on a universe built to be homogeneous. The sixteen classes span bonds, equities and commodities. The five equity classes are the same asset in five places.

Req <- Re[, grepl("_equity$", colnames(Re))]
Ceq <- stats::cor(Req)
Seq <- stats::cov(Req)

w_gmv_eq <- extractWeights(optimize.portfolio(Req,
  portfolio.spec(colnames(Req)) |>
    add.constraint("full_investment") |> add.constraint("long_only") |>
    add.objective(type = "risk", name = "var"),
  optimize_method = "ROI"))

# Effective bets: the reciprocal of the Herfindahl index of the weights. Sixteen
# equal positions score 16, everything in one name scores 1. It counts positions
# the way an investor would, not the way the weight vector's length does.
eff_bets <- function(w) 1 / sum(w^2)

vol_eq <- sqrt(as.numeric(t(w_gmv_eq) %*% Seq %*% w_gmv_eq)) * sqrt(12)

tibble::tibble(
  universe         = c("16 mixed classes", "5 equity classes"),
  mean_correlation = c(mean_cor, mean(Ceq[upper.tri(Ceq)])),
  gmv_vol          = c(p_vol(w_gmv), vol_eq),
  quietest_asset   = c(min(moments$vol), min(apply(Req, 2, ann_vol))),
  effective_bets   = c(eff_bets(w_gmv), eff_bets(w_gmv_eq))
) |>
  dplyr::mutate(gain = gmv_vol / quietest_asset - 1)
#> # A tibble: 2 × 6
#>   universe         mean_correlation gmv_vol quietest_asset effective_bets   gain
#>   <chr>                       <dbl>   <dbl>          <dbl>          <dbl>  <dbl>
#> 1 16 mixed classes            0.354  0.0414         0.0473           1.41 -0.125
#> 2 5 equity classes            0.572  0.158          0.183            3.09 -0.134

The two universes could hardly be less alike. Average pairwise correlation is 0.35 across the classes and 0.57 within equities. And what the optimiser does with them is not alike either: across the classes it holds 1.41 effective positions out of sixteen, because 84% of the portfolio is US_government. Among equities, where nothing is quiet, it has no such option and holds 3.09 of five.

One of those is barely a portfolio and the other is a real one. Now compare what they bought. Minimum variance lands 12.5% below the quietest class series, and 13.4% below the quietest equity market. Twice the diversification, the same discount. The effort and the payoff are unrelated.

Both frontiers terminate at the same point, because the highest-return asset in the mixed universe is an equity market and the optimiser at the right end holds nothing else. What the eleven non-equity series add is entirely at the other end: they extend the frontier leftward from 15.8% down to 4.1% of volatility. Nothing is added above; a floor is added below.

9.4.4 Two data points are not a law, so here are five hundred

The comparison above is suggestive and it is also just two universes. If the minimum-variance level really is set by what is available rather than by how it combines, that should hold on universes nobody designed.

set.seed(1602)

gmv_vol_of <- function(X) {
  w <- extractWeights(optimize.portfolio(X,
    portfolio.spec(colnames(X)) |>
      add.constraint("full_investment") |> add.constraint("long_only") |>
      add.objective(type = "risk", name = "var"),
    optimize_method = "ROI"))
  sqrt(as.numeric(t(w) %*% stats::cov(X) %*% w)) * sqrt(12)
}

draws <- lapply(3:16, function(n) {
  lapply(seq_len(if (n == 16) 1 else 40), function(...) {
    X <- Re[, sort(sample.int(ncol(Re), n))]
    C <- stats::cor(X)
    data.frame(n = n, mean_cor = mean(C[upper.tri(C)]),
               gmv_vol = gmv_vol_of(X), min_vol = min(apply(X, 2, ann_vol)))
  })
})
subu <- do.call(rbind, unlist(draws, recursive = FALSE)) |>
  dplyr::mutate(gain = gmv_vol / min_vol - 1)

c(universes = nrow(subu),
  median_gain = median(subu$gain),
  worst_gain = min(subu$gain),
  best_gain = max(subu$gain))
#>   universes median_gain  worst_gain   best_gain 
#>   521.00000    -0.11736    -0.27560    -0.01341

Across 521 sub-universes drawn from the same sixteen series, the median portfolio lands 11.7% below its own quietest constituent. Not one of the five hundred escapes the band: the smallest discount is 1% and the largest is 28%. The discount is a constant of the exercise, not a property of any particular selection.

Which of the two inputs decides the level, then?

r2 <- function(f) summary(stats::lm(f, data = subu))$r.squared

c(quietest_asset_alone = r2(log(gmv_vol) ~ log(min_vol)),
  correlation_alone    = r2(log(gmv_vol) ~ mean_cor),
  everything           = r2(log(gmv_vol) ~ log(min_vol) + mean_cor + n))
#> quietest_asset_alone    correlation_alone           everything 
#>               0.9795               0.0662               0.9897

The volatility of the quietest available asset explains 98% of the variation in the minimum-variance level. Average correlation, the thing the word “diversification” actually refers to, explains 7%. Handing the regression both of them plus the size of the universe moves it to 99%.

This is worth saying plainly, because “diversification is the only free lunch” is usually offered as though the combination did the work. It does not. Choose the universe and you have chosen the answer to within about an eighth; the optimiser then allocates inside a room whose ceiling height was fixed before it was called. That is the first argument in this book for spending effort on which assets are eligible rather than on the machinery that weights them, and Section 15.1 returns to it.

9.4.5 And it does not survive contact with the future

Everything above is in-sample. Run the same two portfolios out of sample, with a sixty-month rolling estimate and monthly rebalancing, and the ordering reverses. The out-of-sample column is read from the register that Section 24.4 computes, rather than recomputed here, so that the two chapters cannot drift apart:

The tangency portfolio keeps 32% of the Sharpe ratio it promised. Equal weighting, which promised the least, keeps 93% and finishes first.

The best portfolio in this chapter is the worst portfolio in Section 24.4, and the one that requires no estimation at all wins. The gap between the two columns is the subject of the rest of the book.

Exercises

  1. Recompute Table 9.2 with the five money-market series added back to the universe. What happens to the minimum-variance portfolio, and why does the answer make the exercise pointless?
  2. The bootstrap above resamples in twelve-month blocks. Repeat it with blocks of 1, 3 and 24 months. Which block length makes the tangency portfolio look most stable, and what does that tell you about the choice?
  3. Replace the full_investment constraint with weight_sum bounded between 0.99 and 1.01 and rerun the minimum-variance optimisation on every rolling sixty-month window. Count the failures. Then set the bounds to exactly one and count again.
  4. US_credit enters the tangency portfolio at a weight the variance justifies and the skewness does not. Impose a box constraint capping it at 5 per cent and report what it costs in in-sample Sharpe. Is that a price worth paying? Section 10.1 answers it properly.
