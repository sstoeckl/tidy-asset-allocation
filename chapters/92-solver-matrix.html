Appendix C — Solver and Constraint Support

Which solver honors which constraint, measured rather than transcribed. Read alongside Section 13.2, which explains why the distinction between accepts and honors is the one that matters.

Two tables follow. The first is what the package documents: which combinations are supported. The second is what the package does: whether the returned portfolio actually satisfies what was asked. They do not agree, and the disagreement is silent in every case.

R  <- as_xts_pm(sim_class_returns_monthly, date, class, return)
Re <- R - sim_riskfree_monthly$return
N  <- ncol(Re); S <- stats::cov(Re); mu <- colMeans(Re)

sol <- quadprog::solve.QP(2 * S, rep(0, N), cbind(mu, diag(N)),
                          c(1, rep(0, N)), meq = 1)
w_true <- pmax(sol$solution, 0); w_true <- setNames(w_true / sum(w_true), colnames(Re))
sharpe <- function(w) sum(mu * w) / sqrt(as.numeric(t(w) %*% S %*% w))

The benchmark is the long-only tangency portfolio on the sixteen risky class series, solved directly with quadprog and therefore free of anything PortfolioAnalytics might get wrong. Its monthly Sharpe ratio is 0.2861, held in 5 positions.

C.1 What the package documents

Three entries in that table are already misleading, and the chapters say so: position limit is available under ROI only on the maximum-return and minimum-ES mixed-integer paths, not on the mean-variance quadratic program; leverage exposure is documented for ROI’s mixed-integer path alone, but the quadratic path accepts it and returns a long-only portfolio; and turnover under CVXR is a penalty term, not a constraint, so it bends rather than binds. A “no” in the table does not mean an error, either: the constraint is accepted and dropped, which Table C.4 measures.

C.2 What the package does

set.seed(1602)

base <- portfolio.spec(assets = colnames(Re)) |>
  add.constraint(type = "full_investment") |>
  add.constraint(type = "long_only") |>
  add.objective(type = "return", name = "mean") |>
  add.objective(type = "risk",   name = "StdDev")

probe <- function(spec, method, max_pos = NULL, ...) {
  t0 <- Sys.time()
  o <- try(suppressWarnings(
    optimize.portfolio(Re, spec, optimize_method = method,
                       maxSR = TRUE, trace = FALSE, ...)), silent = TRUE)
  secs <- as.numeric(difftime(Sys.time(), t0, units = "secs"))
  lim <- if (is.null(max_pos)) NA_integer_ else as.integer(max_pos)
  if (inherits(o, "try-error")) {
    return(tibble::tibble(solver = method, share = NA_real_, limit = lim, holdings = NA_integer_,
                          verdict = "errors", seconds = secs))
  }
  w <- extractWeights(o)
  if (is.null(w) || anyNA(w)) {
    return(tibble::tibble(solver = method, share = NA_real_, limit = lim, holdings = NA_integer_,
                          verdict = "NA weights, silently", seconds = secs))
  }
  w <- w[colnames(Re)]; h <- sum(w > 1e-6)
  tibble::tibble(solver = method, share = sharpe(w) / sharpe(w_true), limit = lim, holdings = h,
                 verdict = if (is.null(max_pos)) "solved"
                           else if (h <= max_pos) "feasible" else "VIOLATES",
                 seconds = secs)
}

)

The third table takes ROI alone and asks it for the three constraints that Section 12.2 found it does not honor on the quadratic path, each with a bound that binds, and for the two linear paths on which it does honor a position limit.

C.3 The gaps worth knowing

Position limits on the quadratic path. No cardinality formulation exists, so the constraint cannot be honored. On the build this book pins, a position limit (max_pos) on ROI’s quadratic path is dropped without a message: no error, no warning, and the unconstrained weights come back, exactly as on the CRAN release. ROI honors the limit only on its two mixed-integer paths, maximum return and minimum expected shortfall, which it hands to Rglpk. A patch that refuses the quadratic call is proposed upstream, not in the pinned build. See Appendix D.

Leverage exposure on the quadratic path. gmv_opt_leverage() builds its ROI::OP() without the variable bounds that gmv_opt() passes, so ROI’s default of \(x \ge 0\) overrules the box and the long-only minimum-variance portfolio comes back, with gross exposure of one. Under CVXR the constraint is not written at all. Section 12.2 solves the same problem by hand.

pso and GenSA under a position limit. Both accept the constraint and return portfolios of 15 and 16 positions against a limit of 4, most or all of the universe. This is not a convergence failure — the search never encoded the restriction.

An exact full_investment constraint. On the CRAN release, min_sum == max_sum is written as two opposing inequality rows, which quadprog reports as infeasible; ROI then returns NA weights without raising. Measured with the CRAN release on dataset 6.2.0, as Section 9.2 does, 30 of 312 rolling sixty-month minimum-variance windows fail this way; the build this book pins carries the fix (Appendix D). The metaheuristics meet the same constraint differently, warning that it is “restrictive” and advising min_sum = 0.99, max_sum = 1.01 — which is advice to leave a percent of the portfolio uninvested in order to make a solver comfortable.

Solver names under CVXR. Dispatch happens on the second element of optimize_method, matched against a hard-coded list. CLARABEL is installed, is CVXR’s own default, and is not on the list; asking for it returns an object with no weights and no error. See Section 9.2.

Risk budgeting and diversification. Neither has a convex formulation here. Under ROI a diversification target is accepted and ignored without a message, as Table C.4 shows, so every result in Section 14.1 and every diversification floor comes from a search whose accuracy Table C.2 measures.

C.4 How to read all of this

The single practical conclusion, and it is the one Section 13.2 ends on: audit the answer. Check that the weights sum to what you asked, that none is negative under a long-only constraint, and that the number of positions respects the limit. Four lines, run every time, and they catch every failure tabulated above.
